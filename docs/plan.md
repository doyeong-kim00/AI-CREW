## 기술 결정
| 항목 | 결정 | 이유 |
|---|---|---|
| 구조 | `index.html` 한 장, 바닐라 JS, 외부 라이브러리 없음 | 서버·빌드 없이 더블클릭으로 실행 |
| 데이터 | JS 안에 가상 데이터 생성 함수(고정 시드) | 매번 같은 숫자 → 정답 대조 가능 |
| 계산 | 계산 엔진을 화면 코드와 분리(`calc` 묶음), 반올림은 표시할 때만 | 정답 대조, 원값 검산 |
| 자가 검산 | 정답.md 예시 A~G를 앱 안에서 돌려 통과/실패를 설정 화면에 표시 | 조각마다 자동 확인 |
| 차트 | SVG 직접 그리기 (폭포형, 추이선, 쌓은 막대) | 라이브러리 없이 폰에서 가볍게 |
| 저장 | localStorage(메모·확정·설정), try/catch | 실패해도 앱 작동 |
| 레이아웃 | 모바일 우선 CSS, 960px 이상 2단 | spec R5 |
| 디자인 | 기존 시험판과 다른 새 디자인. 조각 1에서 색·글꼴·카드 규칙을 먼저 정함 | 사용자 결정 |

## 확인 방법 (조각마다 공통)
1. **정답 대조**: 설정 화면의 자가 검산(정답.md 예시 A~I + 가상 데이터)이 모두 통과인지 본다. 하나라도 실패면 다음 조각으로 넘어가지 않는다. `index.html?selftest`로 열면 결과가 왼쪽 위에 뜬다.
2. **검사가 진짜 잡는지**: 새 검사를 넣으면 일부러 고장 낸 복사본(원본은 그대로)에서 실패하는지 확인한다.
3. **계산 엔진을 바꾼 조각**: `python validation/tools/diffcheck.py index.html 결과.html`로 무작위 교차 비교(7,501항목)를 다시 돌린다.
4. **폰·PC 캡처**: Edge 헤드리스는 창을 496px보다 좁게 못 만들므로, 폰은 **360px iframe 묶음 페이지**로 찍고 `?layoutcheck`의 `overflow=false`를 확인한다. PC는 1280px로 직접 찍는다.
5. **기록**: `validation/조각N.md`에 통과/실패와 고친 점, `ai-log/조각N.md`에 AI 요청·결과·내 판단을 남긴다. 조각마다 커밋하고 GitHub에 올린다.

## 리스크
- 시간이 모자라면 조각 7의 PC 큰 차트와 R1.6(쌓은 막대)을 줄이고, 조각 1~6을 먼저 완성한다.
- 폭포형 차트가 폰 너비에서 좁으면 가로 막대형 폭포로 바꾼다(spec R3.3 범위 안).
- GitHub Pages가 "반응형 웹" 조건에 맞는지 강사 확인 필요. 앱 안 AI 기능이 필수인지도 확인.
- 기존 시험판 코드는 붙이지 않는다. 계산 결과 대조용으로만 참고한다.
