# 임원 검수 — 납품 받을 수 있나? (2026-11-13)

> 관점: 하이젠알앤엠 원가 담당 임원. 기준: "다음 달 월 마감부터 우리 원가팀이 이걸로 일할 수 있나?"
> 받을 수 있을 때까지 검수 → 보완을 반복한다.

## 1차 검수 — 반려
| # | 지적 | 판정 | 조치(계획) |
|---|---|---|---|
| 1 | 우리 데이터를 넣을 방법이 없다. 가상 데이터만 보여주는 도구는 업무에 못 쓴다 | **반려** | 견적·실적·지표 파일 불러오기(엑셀 xlsx·CSV), 열 이름 자동 맞추기, 검사 결과 보고 (spec R6) |
| 2 | 결과를 보고·공유할 수 없다. 메모가 이 브라우저에만 있다 | **반려** | 결과·예외를 엑셀용 CSV로 내보내기, 메모·확정 백업 파일 받기/불러오기 (spec R7) |
| 3 | 검토 진행률이 안 보인다 (기획서 5.3 지표) | 보완 | 검토율 = 확정 ÷ 확인 필요, 예외 비율 = 예외 행 ÷ 전체 행 |
| 4 | 어느 파일·어느 시점 숫자인지 모른다 | 보완 | 상단 데이터 출처 배지(가상 / 파일명·불러온 시각) |
| 5 | 한국어 엑셀 CSV(CP949)는 한글이 깨질 것 | 보완 | UTF-8 실패 시 CP949(euc-kr)로 다시 읽기 |
| 6 | 양식을 모른다 | 보완 | 예시 파일(양식) 받기 — 지금 가상 데이터를 그대로 양식으로 |
| 7 | 월간 보고용 인쇄 | 보완 | 인쇄용 화면(탭바·버튼 숨김) |
| 8 | 숫자 신뢰(검산 206항목 + 교차 7,501), 데이터가 밖으로 안 나감 | 좋음 | 유지. 불러온 데이터도 브라우저 안에서만 처리 |

### 1차 보완 결과
반려 1 → 조각 9(데이터 불러오기), 반려 2 → 조각 10(내보내기·백업), 보완 3~7 → 검토율·예외 비율·출처 배지·CP949·양식·인쇄. 자가 검산 261/261.

## 2차 검수 — 반려 (실제 파일을 넣는다고 상상하면)
| # | 지적 | 판정 | 조치 |
|---|---|---|---|
| 1 | 견적 파일에 v1·v2 수정본이 같이 있으면 "값이 다른 중복"으로 **전부 계산 보류**된다 (기획서 H3) | **반려** | 견적 버전 처리: 프로젝트마다 비교 기준 버전 하나만 고름(기본 **최종**, 설정에서 **최초**), 다른 버전은 상세에 "v1·v2 중 v2 기준"으로 표시 (spec R6.10) |
| 2 | 원가팀 견적 파일에 판매금액·생산수량이 없을 수 있는데 지금은 필수라 파일 전체 거절 | 보완 | 두 열을 선택으로. 없으면 프로젝트 차이 분석은 그대로, 기종 개당 원가·이익률만 "정보 없음" (spec R6.11) |

| 4 | 누가 확정했는지 안 남음 | 보완 | 확정할 때 운영 담당자 이름을 함께 저장, 결과 CSV "확정자" 열 |

## 최종 판정 — 납품 수락 (조건부)
| 기준 | 판단 |
|---|---|
| 우리 데이터로 쓸 수 있나 | 예 — 엑셀·CSV(CP949), 열 이름·날짜 모양 차이, 견적 버전, 빠진 판매금액·수량까지 처리. 못 넣는 행은 버리지 않고 예외로 |
| 숫자를 믿을 수 있나 | 예 — 손계산 정답 285항목, 독립 구현 교차 7,501항목, 고장 복사본으로 검사 자체도 확인 |
| 결과를 보고·공유할 수 있나 | 예 — 결과·예외 CSV(엑셀), 인쇄/PDF, 메모·확정 백업, 확정자·시각 기록 |
| 직원이 혼자 쓸 수 있나 | 예 — 첫 화면 안내, 사유 범례, 판단 불가 이유, README 매달 쓰는 순서 |
| 규모 | 2,000개 × 12재료 1초 미만, 저장 한도 안 |
| 데이터 보안 | 브라우저 밖으로 안 나감 |

**수락 조건 (납품 뒤 Kick-off에서):** ① 실제 견적·실적 파일 1개월분으로 불러오기 확인 ② 확인 필요·기종 주의 기준값을 우리 규모에 맞게 확정 ③ 팀 공유가 필요하면 서버 저장(다음 단계) 검토.
이 조건은 앱 결함이 아니라 회사 쪽 결정·데이터가 있어야 할 수 있는 일이므로, **현재 결과물을 납품 받는다.**
