# 조각 1 검증 — 화면 뼈대 + 디자인 규칙

> 날짜: 2026-11-12 · spec: R5 (R5.2·R5.6 개정 포함) · 결과: **통과**

## 통과 기준과 결과
| 기준 | 결과 | 근거 |
|---|---|---|
| 360px에서 가로 스크롤 없음 (화면 4개) | 통과 | `조각1_폰360_4화면.png` 각 화면 왼쪽 위 `vw=360 scroll=360 overflow=false` |
| 1280px에서 가로 스크롤 없음 | 통과 | `조각1_PC_프로젝트.png`, `조각1_PC_설정.png` |
| 탭 전환 (기종/프로젝트/예외/설정) | 통과 | 주소 `#kinds` `#projects` `#exceptions` `#settings`로 각각 열림, 선택 탭 강조 |
| 폰: 앱바 + 하단 탭바 4개 + 큰 제목 | 통과 | 360px 캡처 |
| PC: 왼쪽 사이드바 + 2단(목록·상세) | 통과 | 1280px 캡처 |
| "가상 데이터" 항상 보임 | 통과 | 폰 앱바, PC 사이드바 아래 |
| 터치 대상 44px 이상 | 통과 | 탭 높이 68px, 사이드바 항목 44px (CSS) |
| 움직임 줄이기 설정 존중 | 통과(코드) | `prefers-reduced-motion`에서 스켈레톤·전환 애니메이션 끔 |

## 검증하다 발견한 것
- **Edge 헤드리스는 창을 496px보다 좁게 만들지 못한다.** `--window-size=360`으로 찍으면 앱은 496px로 그려지고 캡처만 360px로 잘려, 넘치는 것처럼 보였다(앱 버그 아님, 496px에서도 overflow=false).
- 해결: 360px 너비 iframe 4개에 앱을 띄워 한 장으로 찍는다(iframe 안에서는 `innerWidth=360`). 이후 조각도 이 방법으로 폰 화면을 확인한다.
- 잘린 캡처 3장은 오해를 막기 위해 지웠다.

## 디자인 방향 결정 (같은 조각 안에서)
- 1차 디자인(흰 카드 + 파란 강조 + 알약 탭)에 대해 사용자: "너무 다른 사람들이랑 비슷해"
- 과제 소재에서 끌어온 시안 3개(A 구리 설계도 / B 원가 장부·도장 / C 공장 계기판)를 같은 화면·같은 가상 숫자로 비교 → `디자인_시안_비교.png`
- 사용자 선택: **C 공장 계기판** → CLAUDE.md 디자인 규칙에 고정 후 index.html 다시 적용
- C 적용 후 다시 캡처: 360px 4화면 overflow=false, PC 1280px 정상 (캡처 파일 덮어씀)

## 남은 것
- 실제 폰(갤럭시·아이폰)에서 열어보기는 조각 8(배포 후)에서.
- 웹폰트(Pretendard)는 인터넷이 없으면 맑은 고딕으로 바뀜 — 작동에는 영향 없음.
